Message :
Avec e.position.x = 3.0; sur un Ennemi qui hérite de Mobile et de Visible, le compilateur refuse :
    diamant.cpp: In function ‘int main()’:
    diamant.cpp:52:7: error: request for member ‘position’ is ambiguous
       52 |     e.position.x = 3.0;
          |       ^~~~~~~~
    diamant.cpp:10:10: note: candidates are: ‘Vec2 Entite::position’
       10 |     Vec2 position{0.0, 0.0};
          |          ^~~~~~~~
    diamant.cpp:10:10: note:                 ‘Vec2 Entite::position’
Ennemi contient deux Entite (une dans Mobile, une dans Visible), donc deux position : le nom est ambigu.

Tailles :
Version 1 (héritage ordinaire) :
    sizeof(Entite) : 16
    sizeof(Mobile) : 32
    sizeof(Visible) : 24
    sizeof(Ennemi) : 56
Version 2 (héritage virtuel) :
    sizeof(Entite) : 16
    sizeof(MobileV) : 40
    sizeof(VisibleV) : 32
    sizeof(EnnemiV) : 56
Version 1 : Entite = 16 octets (un Vec2). Mobile = 16 (son Entite) + 16 (vitesse) = 32. Visible = 16 (son Entite) + 1 (glyphe) + 7 de bourrage = 24. Ennemi = 32 + 24 = 56 : deux Entite complètes (2 x 16), une vitesse (16), un glyphe (1) et 7 octets de bourrage.
Version 2 : Entite = 16. Mobile = 8 (pointeur caché vers la base virtuelle) + 16 (vitesse) + 16 (Entite) = 40. Visible = 8 (pointeur caché) + 1 (glyphe) + 7 de bourrage + 16 (Entite) = 32. Ennemi = 56 : une seule Entite (16), mais deux pointeurs cachés (2 x 8), une vitesse (16), un glyphe (1) et 7 octets de bourrage. Les deux pointeurs cachés mangent exactement la place gagnée en retirant la seconde Entite.

Deux positions :
Version 1, après e.Mobile::position.x = 3.0; :
    position vue par Mobile& : 3.0
    position vue par Visible& : 0.0
Il y a bien deux positions dans un Ennemi : la référence Mobile& voit celle de Mobile (3.0), la référence Visible& voit celle de Visible, restée à 0.0.
Version 2, après e.position.x = 3.0; (qui n'est plus ambigu) :
    position vue par MobileV& : 3.0
    position vue par VisibleV& : 3.0
Il n'y a plus qu'une seule Entite partagée : les deux références voient la même position.

Pourquoi jamais :
1. Sans virtual, l'Ennemi a deux positions qui se contredisent ; avec virtual, une seule, mais au prix de pointeurs cachés, d'accès indirects et de constructeurs spéciaux : ici la taille ne diminue même pas (56 dans les deux cas).
2. Chaque nouvel axe (vie, bruit, etc.) ajouté par héritage multiplie les classes et les combinaisons, et le diamant se reproduit à chaque fois.
3. Un Ennemi n'est pas à la fois un Mobile et un Visible : il a une position, une vitesse et un glyphe. On compose (un Transform, un Corps, un Sprite) au lieu d'hériter.
